# Data Attribution: notebooks

Two notebooks on one path. Do **DA1** in the morning: it's the common core. In the afternoon, read the short capsule at the top of each **DA2** stop, in order, then go deep wherever you like. You go deep either by reading the named paper sections or by working through our annotated walkthrough, which derives the same result. Nobody is expected to finish everything.

**Primary source:** Louis Jaburi's Iliad notes, *Data (Attribution) for Alignment* ([web version, with solutions](https://iliad-intensive.org/learning/data-attribution/); [PDF, without](source/data-attribution-nosol.pdf)). In the session we derive the notes together. [`lectures/L0_deriving_the_notes.html`](lectures/L0_deriving_the_notes.html) follows them section by section, one derivation step per slide; where a statement in the notes needs a correction, the slide shows the corrected version and its speaker notes say so. Everything below is a backup and a store of extra material, adapted from Louis's notes (CC BY 4.0), with changes.

Each notebook comes as two files:

- **`<name>.html`**, the reading page. Open it in any browser; the first load needs a network connection for the math typesetting.
  - Worked solutions and hints are folded. "Show all solutions" expands every solution at once.
  - Sections and subsections are folded too, and the contents sidebar lists every walkthrough.
  - Code cells show their output, with the code folded under "Code".
  - Readings carry ARENA-style **Importance** and **Length** scores. Papers the instructor hasn't vetted are listed last, as "Claude-suggested extras".
- **`<name>.ipynb`**, the runnable notebook. It has starter code for the code exercises and blank answer cells. It runs on a CPU in under a minute, and needs numpy, matplotlib, scipy and torch.

## For maintainers

- **Building.** Never hand-edit the `.html` or `.ipynb` files. Each pair is generated by `build_<stem>.py`, using `nbkit_da.py` and `htmlkit_da.py`. These are a copy of the TD kit (`../td/`) with two changes: sibling links are rewritten for `da*` stems, and the contents list includes `###` subsections. The build, `--check` and `--run` work as in `../td/README.md`.
- **Checks.** `checks/da1_core_checks.py` and `checks/da2_methods_checks.py` verify every formula, symbolically or numerically; `checks/L0_checks.py` and `checks/L1_checks.py` do the same for the derivation deck and the L1 slides. `assets/interactive/checks/` checks the filter explorer's JavaScript against numpy.
- **Design.** The spec, including the errata ledger for the source notes, is `../DA_SPECS_v1.md`; the writer brief is `WRITER_BRIEF.md`; review logs are in `../reviews/da/`. The source notes are in `source/`.
