# Training Dynamics: notebooks

Nine notebooks: one on deep linear networks (`td1`), seven on what the knobs of a training run do (`td2_1` to `td2_7`; the small-step expansions in `td2_1` and `td2_2` come before the edge of stability in `td2_3`, where they break), and a closing set of readings with a map of the day (`td2_8`). Pick whatever interests you. Every notebook stands alone, and nobody is expected to finish everything.

Each notebook starts with its readings: after a short introduction and route, a **Readings** section lists every paper of the notebook, grouped by the section it belongs to, each with its scores and a sentence on what it gives. The sections after that are the derivations and walkthrough, one per topic: a short pitch, then a guided route through the derivations, exercises and code for whoever wants it.

Each notebook comes as two files:

- **`<name>.html`**, the reading page. Open it in any browser. Math is typeset by KaTeX, loaded from a CDN, so the first load needs a network connection. Every exercise is followed by its worked **solution**, folded away until you click "Solution", and hints fold the same way. The "Show all solutions" button expands or collapses every solution at once, and printing the page prints them all. Sections are folded, except the Readings: open what you want, or use "Expand all sections". Code cells show their output, figures included, with the code itself folded under "Code". Every reading carries ARENA-style **Importance** and **Length** scores (1–5 dots; the key is under the contents); books are listed separately as reference links. Code exercises show the starter code, with the solution code and its output folded under "Solution (code)". The interactive figures are embedded in the page. Solutions are for everyone, so use them however helps you learn.
- **`<name>.ipynb`**, the runnable notebook. Open it in Jupyter to run, change and finish the code. It has the starter code for each code exercise, with the answer cells left blank. Everything runs on a CPU in a few minutes at most. You need numpy and matplotlib, plus scipy or torch for some notebooks (each page says which).

## For maintainers

- Never hand-edit the `.html` or `.ipynb` files. Each pair is generated by one builder, `build_<name>.py`, from cells defined with the helpers in `nbkit_td.py`: `markdown()`, `reading(..., importance=, length=)` (both scores required, 1–5; books go in `references(book(...), ...)` instead), `answer()` (worked solution), `code()` (shown and run as is), and `code_answer(stub, solution)` (the stub goes in the notebook, the solution is folded on the page).
- Build with `python build_<name>.py` (needs `pandoc` on PATH, plus numpy, matplotlib, scipy and torch). The build executes the solution code cells in order, in one namespace with matplotlib's Agg backend, and captures stdout, stderr and every figure (embedded as PNG). The outputs are cached in `_exec_cache/<name>.json`, keyed on a hash of the code that runs, so a rebuild after a prose-only change takes seconds. `--rerun` forces execution.
- `--check` reports whether the page or notebook is stale. It never executes code, and code changed since the cached outputs counts as stale. `--run` executes the solution code cells and reports the time per cell, and fails on an exception or on a cell over `--budget` seconds (default 60).
- **Page shape (readings first, 2026-10-14).** Intro and route; then one `## Readings` section holding every `reading(...)` of the notebook, grouped under bold per-section headers, with books last via `references(book(...))` (the kit renders a `##` titled exactly "Readings" open by default; see `OPEN_SECTIONS` in `htmlkit_td.py`); then one `##` per topic with a short pitch, a one-line pointer to its papers in the Readings, and, from the `<a id="...-walkthrough">` anchor on, the derivations, exercises (bold paragraphs, not headings) and code. No `###` or `####`.
- The HTML side is `htmlkit_td.py`. Its page template, CSS and KaTeX loader are copied from the MDL kit (`../notebooks/nbkit.py`), plus styles for code, outputs and embedded figures. Don't edit the MDL kit from here. Like the MDL kit, the build fails on unbalanced `<details>`, TeX left outside math, duplicate ids, missing local link targets, and dangling `#anchors` within the page or in a sibling TD page. A missing anchor in an MDL page (`../notebooks/*.html`) only prints a warning, because that day is built elsewhere. `python checks/td_crosslinks.py` checks every cross-notebook and MDL anchor.
- **Links between notebooks.** Builders may write `tdX_name.html#anchor` or one of the older forms (`tdX_name_solutions.ipynb#anchor`, `_exercises.ipynb`). The kit rewrites every one to `tdX_name.html#anchor` on the pages and `tdX_name.ipynb#anchor` in the notebooks.
- **Interactive figures.** `figure(path, text)` links a figure in `assets/interactive/`. On the page, the link is followed by an `<iframe>` of the figure. Each figure ends with a short script that posts its height to the page, so the frame fits it. Without that script the frame falls back to 80% of the window height and scrolls.
- The older exercises/solutions `.ipynb` pairs are kept, unmaintained, in `_old_ipynb/`.
- Pedagogy and content decisions: [`TD_BUILD_DECISIONS.md`](TD_BUILD_DECISIONS.md). Numerical checks: `checks/`. Review logs: `../reviews/td/`. Lecture outlines: `lectures/`; the L2 slides are `lectures/L2_pragmatic_picture.html` (reveal.js, figures from `lectures/assets/L2/make_figures.py`).
